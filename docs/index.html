Drop-in kit for Claude Code

One Claude Code session.
A whole product team.

Drop the kit into a project and your main session becomes the PM. It runs 17 development agents and a 17-agent Figma design studio, with the specs, review gates and house rules that keep every status honest.

The office

A scripted replay, not live data. Click anyone in the tower to see who they are and what they are doing. To watch your own team live, run node scripts/claude-team/office.mjs in your project and open http://localhost:4317.

Who sits where

Thirty-four specialists and a PM, across a seven-floor tower. Every agent has its own scope, tool limits and model.

PM cabin
1 · main session
Turns your brief into testable acceptance criteria, picks a risk tier, delegates to specialists and keeps STATE.md current.
Development floor
17 · opus and sonnet
Builds and verifies code: frontend-dev, backend-dev, motion-dev, senior-dev, security-reviewer, qa-tester, release-engineer and ten more.
Design studio
17 · led by design-director
Researches, designs, audits and usability-tests inside one Figma file, and writes no production code. Up to 12 agents at once, at most 8 writing to Figma.

How a brief moves

The PM checks the real repo state, writes acceptance criteria and picks a risk tier, so a small docs edit never pulls in all 17 agents.

Development track

  1. BriefYou describe it
  2. IntakeCriteria and risk tier
  3. SpecRequirements, design, tasks
  4. BuildUp to 3 in parallel
  5. Review and QAGates set by tier
  6. FinishSTATE.md, token report

Design studio track

  1. D0Research
  2. D1Three concepts, you choose
  3. D2IA, flows, copy
  4. D3Desktop, mobile, RTL
  5. D4Every state
  6. D5Motion, prototype
  7. D6Three independent audits
  8. D7QA, usability
  9. D8Handoff, sign-off

Three tiers decide the gates. Low: a small text, style or docs change gets one relevant review. Normal: a feature or integration gets a full spec, senior and code review, and QA. High: auth, payments, sensitive data or schema adds an architect review, a threat model and expanded tests.

House rules

The guardrails ship with the kit, in its settings, playbooks and scripts. They aren't a promise on a slide.

  1. 01

    Never pushes, never deploys

    The team stops at a report. release-engineer checks release readiness, and you ship.

  2. 02

    Destructive git is denied

    Force-push, git reset --hard, git clean and similar commands are blocked by scoped permissions.

  3. 03

    Done means checked

    VERIFIED COMPLETE only when the checks actually ran. Otherwise it's BLOCKED or NOT RUN, never a pass.

  4. 04

    One agent per part

    Design work is claimed in claims.json first, and overlapping claims are refused.

  5. 05

    The studio waits for your word

    Say start to dispatch the run plan. Say stop to halt new dispatches.

  6. 06

    No generic design

    Every frame is checked against 14 AI-looking tells, from purple gradients to John Doe data.

  7. 07

    Secrets stay in .env

    Never in chat, logs or commits.

  8. 08

    Memory across sessions

    A SessionStart hook loads STATE.md, so work picks up where it left off.

Front desk

Move the team into your project in three steps.

  1. 1

    Clone the kit

    git clone https://github.com/abdulrehmankz1/claude-team-kit.git
  2. 2

    Install it into your project

    powershell -ExecutionPolicy Bypass -File .\claude-team-kit\install.ps1 -Target C:\path\to\your-project

    It copies every kit file, skips any that already exist, and creates CLAUDE.md or adds the team section to yours. On macOS or Linux, copy the folder contents into your project root by hand.

  3. 3

    Restart Claude Code and brief the PM

    onboard this project using the team kit

    For design work, connect the figma MCP server with /mcp, run claude --agent design-director, review its run plan and say start.

Needs a recent Claude Code, Node.js, and Python 3 with PyYAML for the kit validator. Tests and visual diff use Playwright and pixelmatch. When a job is done, node scripts/token-report.mjs shows token usage by model, area and agent.
